# Profile community features

## Goal

Make the profile README feel like a live operator console: profile content, community notes, and project ideas are available from the README.

## Behavior

- The terminal uses a black and gold shell style and highlights Gustavx404's role, focus areas, and public projects. Project names and descriptions are fetched with one read-only GitHub API request during the asset build. Omit contact links, account metrics, and unrelated activity.
- Do not present Nmap, Gobuster, Hydra, or Burp Suite as tools for reading GitHub profile data. The profile is not an authorized scan target; use GitHub's API for public account information.
- A visitor submits a short message using an issue form. Open guestbook issues are rendered as plain text in a bounded README section. Closing an issue removes it from the wall.
- A project idea is submitted through an issue form. Readers vote by adding a 👍 reaction to that issue; the README shows current counts. A scheduled sync refreshes counts because reactions do not emit a supported workflow event.
- User-submitted text is length-limited and escaped before it is written into Markdown.

## Constraints

- All rendered graphics and README updates are generated by this repository's scripts and GitHub Actions.
- Do not claim real security findings or engagements in the profile terminal.
- Keep community content bounded and use GitHub's issue lifecycle for removal/moderation.
